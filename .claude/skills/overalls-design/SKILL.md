# Overalls design system

Overalls is an AI-first developer platform that you own. Its public face is
plain text on a character grid: one typeface, four colours per theme, square
corners, box-drawing diagrams. It reads like a well-kept workshop manual, not a
marketing site. The look comes from the Kittens web UI, which uses
[The Monospace Web](https://owickstrom.github.io/the-monospace-web/) by Oskar
Wickström (MIT) (ADR-0161), extended for a public site.

The live reference is this repository: `index.html`, `architecture.html` and
`self-host/*.html`, generated by `tools/site/`. When in doubt, copy what's
already there.

## Principles

1. **Everything sits on the grid.** A cell is `1ch` wide by `var(--line-height)`
   (1.2rem) tall. Horizontal sizes go in `ch`; vertical sizes in multiples of
   the line height. Borders are 2px, and padding subtracts the border so boxes
   stay on the grid.
2. **Four tokens, two themes.** `--text-color`, `--text-color-alt`,
   `--background-color` and `--background-color-alt`, defined for light and dark.
   No other colour exists. State is shown by text, weight or inverse video,
   never by colour alone.
3. **Text, not pictures.** Icons are Unicode glyphs. Diagrams are box drawing
   in `<pre>`. The brand mark is a word plus two box-drawn kittens in one pair of overalls. No icon sets, no
   images, no SVG illustrations (the favicon is the only exception).
4. **Semantic HTML first.** Headings, tables, `dl`, `details`, `figure`, `ol`
   and `ul` are styled at element level. Reach for a class only when an element
   can't express the layout.
5. **Nothing from another origin.** Fonts, CSS and JS are served from the site
   itself. No CDNs and no hosted fonts. The one exception is Simple Analytics,
   served through the `api.ghuntley.com` proxy (`ANALYTICS` in `tools/site/layout.py`),
   which `check.py` allows by host name.
6. **Honest copy.** Every feature claim is backed by the source repo and carries
   a status label. If the code doesn't do it, the site doesn't say it.

## Workflow

1. Read [references/visual-system.md](references/visual-system.md) for tokens,
   type and layout rules, and [references/components.md](references/components.md)
   for copy-paste HTML recipes.
2. Write copy using [references/voice.md](references/voice.md). Check any claim
   against `~/src/kittens` on `origin/main` (the main checkout may be on an old
   branch). Pick status labels with the rules in that file.
3. Draw diagrams on a character canvas: see [references/diagrams.md](references/diagrams.md)
   and `scripts/canvas.py`. Never hand-align box drawing.
4. For brand use (name, wordmark, mark, favicon, taglines), follow
   [references/brand.md](references/brand.md).
5. For this site: edit `tools/site/*.py`, run `python3 -I tools/site/build.py .`,
   and don't hand-edit generated HTML unless you also change the generator.
   CSS lives only in `assets/css/site.css`.
6. Verify with [references/verification.md](references/verification.md):
   link and colour checks, then screenshots in light, dark, 1280px and 390px.
   Look at the screenshots before you claim it works.

## Starting a new project in this style

Copy `assets/` from this skill: `site.css` (complete stylesheet), `site.js`
(appearance switch and copy buttons), `fonts/` (JetBrains Mono woff2 plus the
OFL), `favicon.svg` and `monospace-web-LICENSE.md`. Then start from
`assets/page-template.html`. Keep the credits in the footer: The Monospace Web
is MIT and JetBrains Mono is OFL 1.1.

## Never

- Rounded corners, drop shadows, gradients, blur, or transitions beyond `button:active`.
- Colour literals outside the token block (print overrides are the one exception).
- A second typeface, a font size outside the type scale, or centred body text.
- Emoji. Use glyphs from the list in visual-system.md.
- Stock marketing words: "seamless", "blazing", "revolutionary", "unlock", "empower".
- Status-free feature claims, or claims the source repo doesn't support.
- Implying there's a hosted Overalls service. It's software you run; there's no sign-up.
