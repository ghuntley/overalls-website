An AI-first developer platform that you own.

Overalls runs persistent Firecracker microVMs on hardware you control. Each machine keeps its disk, name and address when you stop, start, resize, clone or move it. You use it from a browser terminal, over SSH or with the overalls CLI.

It's open source under the MIT licence. There is no hosted version to sign up for: you install it and run it yourself.

What you get

STABLE built and covered by acceptance tests · PREVIEW works, with rough edges · EXPERIMENTAL still being built

Machines

Persistent microVMs

STABLE

Each machine is a Firecracker guest with its own kernel and a ZFS disk. Stopping it keeps the disk. Disks go up to 500 GiB.

Clone, resize, relocate

STABLE

Clone a machine into an independent copy. Resize CPU and memory up or down, and grow the disk. Move a stopped machine to another host; it keeps its name, identity and address.

Tools already installed

STABLE

Linux guests come with Podman (Docker-compatible), git and the GitHub CLI, tmux, Neovim, ripgrep, jq, direnv and devenv installed. Your Linux login, such as u200001, is the same on every machine.

Caching HTTP proxy

STABLE

Guest downloads from apt, Nix, pip, npm and the like go through Brady. It fetches only from verified upstreams and caches public, anonymous responses, so the second machine to install a package gets it from the cache.

Locked-down profile

STABLE

For customer material: no outbound network, no sharing, no web exposure, and SSH for the owner only.

Operating systems

NixOS

STABLE

The default guest. Declarative and reproducible, with Nix and devenv ready for per-project environments. You can build your own variant with extra NixOS modules.

Ubuntu 26.04 LTS

STABLE

Built with Nix from pinned package snapshots, so every build of the image is identical. Add your own packages with a lockfile.

Windows Server 2025

STABLE

Booted from firmware under a patched Firecracker, with guest agents for readiness, SSH and the terminal.

Working on a machine

Browser terminal

STABLE

Run many persistent terminals per machine from a browser tab. People you share with start in watch mode and can take control and hand it back.

SSH management

STABLE

ssh <gateway> new, ls, start, stop and rm, with --json and retry-safe request IDs for scripts. One wildcard SSH profile connects you to every guest.

Public web apps

STABLE

Each machine can serve HTTPS on its own subdomain under apps.<your-domain>. Audi runs DNS and ingress for this.

Browser editor

PREVIEW

A personal editor built from Microsoft's official Code OSS source, with Open VSX extensions, running as you inside the guest. It is verified on NixOS; Ubuntu support is partial.

Collaboration

Share with coworkers

STABLE

Give a coworker access to one machine with an access-control role. Viewers watch the terminal, operators can also take control of it, and managers can also start, stop, delete and re-share the machine. The owner can't be removed. Cedar checks every action when it runs, so revoking access takes effect even on pages that are already open.

Teams

STABLE

Owners, admins and members share a pool of machines, integrations and secrets, so a team's environments don't belong to whoever happened to create them.

Starting from a repository

Repo launch links

STABLE

https://<your-domain>/#https://github.com/OWNER/REPO creates a machine with that repo checked out in /workspace/REPO. If you aren't signed in, the launch picks up again after you sign in.

Browser extension

STABLE

One toolbar click on a GitHub, GitLab, Codeberg or Bitbucket Cloud repository opens it in a new machine on your deployment. It sends only the repository's origin and path, never page contents. Your deployment serves the Chrome and Firefox packages.

AI

Claude Code and Codex

STABLE

Pre-installed on every guest image that supports them, and ready to use. They're already pointed at Ziggy, so there's nothing to configure: no API keys or credentials are installed on the machine.

Inference without keys

STABLE

Guests call https://llm.internal for OpenAI and Anthropic models. Ziggy adds the provider credentials outside the guest and records usage per account, so no API key ever lives in a VM.

Integrations without keys

STABLE

Named integrations at <name>.integration.internal let guests call external APIs and peer VMs. Galileo adds the credentials at the edge, so a machine can use a secret without being able to read it.

Agent threads

PREVIEW

Each machine has threads of AI agent work. Sending a prompt wakes a stopped machine, and the agent's tools run inside the guest. You can also prompt from your terminal after approving it in the browser.

Running the platform

Node maintenance

STABLE

Take a Lilly host out of service without losing anyone's work. Evacuation moves its machines to other Lilly hosts one at a time; each keeps its identity, disk, sharing and address, and you approve any long downtime first. A drain stops machines in place instead. When the host is empty you can bring it back or retire it.

Off-site backups

STABLE

Restic backs up to any S3-compatible bucket: guest disks from native ZFS snapshots, a dump of Marshall's PostgreSQL, host identities and keys. Running guests sync first and are never paused. Built-in checks read the backups back to prove they restore.

Multi-host fleet and HA

EXPERIMENTAL

Several Marshall instances and many Lilly hosts are supported, and failure and recovery have been tested locally. Acceptance testing across hosts and under load is still open.

Inception

EXPERIMENTAL

A 16 vCPU guest that runs a whole Overalls stack inside itself, including nested Firecracker guests. Useful for working on Overalls with Overalls.

How it fits together

Marshall is the web app and control plane, a Phoenix and Ash application backed by PostgreSQL. Lilly runs on each host. It starts Firecracker guests on ZFS and connects to Marshall over HTTPS to report capacity and receive commands. Porsche handles management over SSH, and Audi serves DNS, guest SSH and web apps. Each guest gets an isolated network, and traffic between guests is blocked.

A taste

Every management command works in the browser, at an interactive SSH prompt or as a one-off ssh command. Add --json when a script is reading the output.

$ ssh <gateway> new --name scratch
$ ssh <gateway> ls
$ ssh <gateway> resize scratch --cpu 4 --memory 8192
$ ssh <gateway> clone scratch --name scratch-copy --request-id copy-1 --no-wait
$ ssh <gateway> share add scratch colleague@example.com operator
$ overalls open https://github.com/OWNER/REPO

<gateway> is the SSH host name of your own Porsche gateway. See your first machine.

Run it yourself

Overalls is a set of NixOS modules plus tools for installing and enrolling bare-metal hosts. Your fleet is defined in a Git repository: you fork Overalls, declare your hosts, and each host keeps itself up to date from your main branch. You can start with one server and add hosts later.

  1. Read the requirements and fork the repo
  2. Install NixOS on a bare-metal host
  3. Deploy Marshall, PostgreSQL, email and TLS
  4. Enroll Lilly hosts and publish guest images
  5. Sign in and create your first machine
  6. Updates, drains, backups and logs
Hardware
x86_64 bare metal with a working /dev/kvm. The host tool can discover Hetzner dedicated and EC2 bare-metal servers.
Operating system
NixOS 26.05, installed for you from a rescue or Ubuntu system
Storage
ZFS, which holds the guest disks
Services
PostgreSQL with TLS, and an authenticated SMTP relay for sign-in links
Network
A domain you control. Certificates come from ACME, by HTTP-01 or Route 53 DNS-01.
Your laptop
Nix with flakes, and a Git server your hosts can read from

Questions

Is there a hosted Overalls I can sign up for?

No. Overalls is software you run on your own machines, and this site is the project's home page. Any "sign in" mentioned in these docs is your own deployment's sign-in page.

What does it cost?

Nothing. It's MIT-licensed; you pay for your own hardware, bandwidth, email relay and inference. Ziggy forwards model calls to OpenAI and Anthropic using your own provider accounts.

Can I run it on a single server?

Yes. A single Marshall instance with local PostgreSQL is a supported deployment, though it has no redundancy (ADR-0048 ↗). You can add Lilly hosts later. A resilient deployment needs independent hosts and a tested plan for database recovery.

Why Firecracker rather than containers?

Each machine gets its own kernel, its own disk and an isolated network, so you can run Podman, systemd services or anything else that expects a real Linux machine. A machine with a working setup stays that way between sessions.

Does it need Kubernetes?

No. It's NixOS modules, systemd units and a few Elixir and Rust services. Hosts install from a reviewed plan and then poll your Git repository for updates.

Why "Overalls"?

They're workwear: what you put on before getting your hands dirty. The first production host was also called overalls, and its sibling is dungarees.
