Enroll hosts and images

A Lilly host only runs guests once Marshall knows about it. Enrolling registers the host as disabled, issues it a revocable credential encrypted to that host, and leaves it to you to enable scheduling.

Needs
An installed host with its receipt, and administrative SSH to both the host and a Marshall host
Credential
Five years by default, revocable at any time, rotated explicitly

1. Declare the Lilly role

Add this to the host's host.json before installing, so the base system includes the identity helper:

"lilly": {
  "controlPlane": "https://control.internal.example:5443",
  "egressInterface": "eth0",
  "credentialTtlSeconds": 157680000,
  "overheads": {"cores": 1, "memoryBytes": 1073741824, "storageBytes": 1073741824}
}

Host names for Lilly hosts can be at most 26 characters. Don't set Lilly host or pool IDs by hand; they're generated.

The control-plane URL reaches Marshall's private fleet listener. If it uses your own CA, set services.lilly.controlPlaneCAFile in the host's configuration.nix to the installed CA bundle, such as /etc/overalls/service-ca.crt.

2. Prepare the enrollment

Deploy the Marshall release and its migration first. Then, from your checkout:

tools/buck2 run //:host -- prepare-enrollment --host NAME --root . \
  --target admin@installed-host --marshall-target admin@marshall-host \
  --identity /private/admin-key --known-hosts /private/known-hosts \
  --install-receipt /private/host-plan.installed.json \
  --recovery-key /private/recovery-key

This registers a disabled host and writes the NAME-git and NAME-lilly ciphertext, plus public registration data in lilly.binding. It doesn't commit, push or enable anything. If it's interrupted, run the identical command again; its journal resumes the work without issuing a second credential.

3. Activate and enable

Push the changes and activate the commit with tools/buck2 run //:host -- enroll --revision …, as in provisioning. Once the host reports ready, enable it from a Marshall host with the operator CLI:

bin/marshall eval 'Marshall.Operations.CLI.main()' show NAME
bin/marshall eval 'Marshall.Operations.CLI.main()' enable HOST_UUID

Operator commands run as a separate process with PHX_SERVER=false, never through a serving node's console. They print only public identities.

4. Guest images

Images have immutable sha256: identities. The shared catalog in fleet/guest-images.nix selects NixOS, Ubuntu, Arch Linux, AlmaLinux, Windows and the reviewed FreeBSD and OmniOS images, plus an experimental Android SDK variant of NixOS. Entries name packages from overallsPackages, for example:

[
  { name = "NixOS"; package = overallsPackages.guest; }
  { name = "Ubuntu 26.04 LTS"; package = overallsPackages.ubuntuGuest; }
  { name = "Windows Server 2025"; package = overallsPackages.windowsGuestPublished; }
]

Use the same staged catalog on every Lilly host and register the selected manifests with Marshall. Lilly seals image templates within its configured budget and clones guest disks on demand. Set services.marshall.defaultImageId to a registered image to choose the default for new machines.

Build the standard Ubuntu image through Buck2:

image=$(cat "$(tools/buck2 build --show-full-simple-output //:package-guest-ubuntu)")
ls "$image"
# kernel  initrd  rootfs.ext4  manifest.json

For custom images, use mkUbuntuGuest with a reviewed APT lock, or the NixOS guest builder's extraModules. The OS matrix ↗ records each family's capabilities and verification limits.

Windows installation isn't byte-identical from build to build. windowsGuestPublished selects one sealed windows-v1 image through the signed Overalls cache and refuses a cache miss. To update it, build once with the source builder, retain the installation evidence, seal disk.raw, firmware and manifest.json, and review their digests and recursive NAR hash. Update the publication and manifest pins together. Publish that exact directory, verify signature-checked substitution on every host, then activate the catalog. Follow the Windows publication procedure ↗.

5. Porsche on your Marshall hosts

Porsche, the SSH gateway, runs on the same hosts as Marshall and listens on port 22 of the same public addresses your apex domain points at. Port 443 on those addresses serves the browser and port 22 serves Porsche, so people manage machines with ssh <your-domain>. There's no separate gateway address or DNS record.

  1. Move administrative SSH to port 2222 first. Activate OpenSSH on both 22 and 2222, check that you can log in on 2222 (with sudo if you need it), then activate a configuration without 22. The module refuses to start Porsche on port 22 until administrative SSH is on 2222. From then on, pass --ssh-port 2222 to the bootstrap tool.
  2. Issue a gateway credential for each Porsche host. Each host gets its own token and gateway name: 
    bin/marshall eval 'Marshall.Operations.CLI.main()' gateway-prepare /private/porsche-host1.token
bin/marshall eval 'Marshall.Operations.CLI.main()' gateway-configure porsche-host1 /private/porsche-host1.token
    Encrypt the token into that host's porsche secret bundle as PORSCHE_GATEWAY_TOKEN.
  3. Enable Porsche alongside Marshall: 
    services.openssh.ports = [ 2222 ];
services.porsche = {
  enable = true;
  bindAddress = "192.0.2.10";
  controlPlane = "https://control.internal.example:5443";
  publicOrigin = "https://example.com";
  caFile = "/etc/overalls/service-ca.crt";
  credentialFile = "${config.services.overallsSecrets.bundles.porsche.directory}/token";
  secretUnits = [ config.services.overallsSecrets.bundles.porsche.unit ];
  openFirewall = true;
};

Replace 192.0.2.10 with the host's primary public address. When Audi shares this host, bind its gateway to a different explicit service address: both gateways listen on port 22, and Audi also needs ports 80 and 443. The modules reject overlapping SSH listeners. Keep publicOrigin on the public browser domain; controlPlane uses the private fleet endpoint.

Before starting either gateway, configure Marshall's dedicated SSH host CA with services.marshall.sshHostCa.publicKey, keyFile and retirement, alongside services.marshall.ingress.zone. Deliver the private signer only to Marshall through an encrypted secret output and list its preparation unit in services.marshall.secretUnits. Follow the SSH host CA custody procedure ↗.

Porsche presents a host certificate signed by that CA. The overalls installer adds that CA to people's known_hosts, so ssh <your-domain> verifies without trust-on-first-use. Porsche reports readiness on /run/porsche/status.sock, and automatic updates wait for it. Rotating a gateway credential ends that gateway's open sessions until it loads the new token.
